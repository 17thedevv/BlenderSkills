# Real-time integration assessment

The study distinguishes two kinds of output: static snapshots of an actual Blender sewing/cloth solve at matching mannequin poses, and one neutral drape clone bound with ordinary armature weights. A favorable simulated pose is not evidence that the neutral skinned mesh will behave the same way. No live cloth solver is present in the prototype's visible frozen mesh; no VRM export/runtime test was run.

| Work item | Required production action | Current status / risk |
|---|---|---|
| Panel seams and topology | Recut panel dimensions/armhole and obtain accepted silhouette first. Weld documented seam pairs only; preserve open cuff and deliberate underarm vent. Retopologize concentrated shoulder/underarm folds with evenly spaced deformation loops and a gusset if justified by the design | Frozen meshes currently average still-separated sewing endpoints before welding. This can conceal a large solver gap; it does **not** prove successful sewing. Existing crumples should not simply be retopologized into a production mesh |
| Retopology density | Keep sufficient loops around armhole/cuff and broad fold anchors; reduce surplus interior cloth samples after visual acceptance. Avoid building runtime deformation into sharp, dense frozen wrinkle fans | Working quad grids are editable but not production optimized. Original character topology stays unchanged |
| UV | Metric pattern UVs are working coordinates with islands outside 0–1. Create a deliberate non-overlapping atlas, matching texel scale, seam padding and seam placement; separate inner/outer surfaces only where needed | No textures or production UV layout added. Pattern UVs are not an export-ready texture atlas |
| Thickness and normals | Decide whether to bake Solidify before export, preserve inward cavity/cuff faces and consistent winding; avoid duplicated hidden front/back shells | 1.6mm thickness is a preview modifier. Exported triangle count and resulting shading are untested |
| Weights | Transfer body weights only as an initial guide. Smooth chest/shoulder/upper-arm transition; keep free bag cloth off lower-arm motion where appropriate. Check neutral, +30°, horizontal and elbow bend | The rig-only clone uses a heuristic three-bone field, normalized but not production painted. Visible stress failures remain |
| Pose correctives | Capture accepted target shapes, convert differences into the mesh's bind space, test interpolation between poses and symmetry. Use elbow/armhole corrections where bones alone are insufficient | No corrective shape keys are generated. Frozen neutral/30°/horizontal objects are static evidence, not rig-driven correctives. Automatic Blender drivers do not constitute a portable runtime mapping |
| Secondary bones | After form/weights approval, consider short sleeve-bag chains with controlled cloth-region weights and torso/arm colliders. Evaluate sleeve cuff vs forearm contacts | No bones were added to the copied rig. Spring bones approximate secondary motion, not fabric stretch/seam/contact solving |
| VRM | Export a complete approved humanoid separately; verify rest pose, skin weights, expressions and MToon. Confirm any custom corrective-morph controller in the intended runtime. Reimport and visually test supported poses | This isolated mannequin scene is not a deliverable VRM avatar; facial expression delivery and garment runtime behavior are NOT_TESTED |

Blender cloth simulation/cache is an authoring result, not physics that automatically runs inside VRM. VRM's [spring-bone extension](https://vrm.dev/en/vrm1/springbone/) is a separate bone-based secondary-motion system. Morph geometry may be transportable, but automatic arm-angle-driven garment correction requires a tested runtime controller; Blender driver logic must not be assumed portable.

If a future accepted drape requires extensive corrective morphs or specialist cloth solving for every pose, compare that maintenance cost against a manually authored, licensed real-time garment base. This study measures solver time, not Warudo FPS or GPU memory. No full-character rebuild, integration, export or decoration is authorized by the experiment's completion.
